# 핵심 개념 문서 (Concepts)

V² Engine을 이루는 핵심 개념을 하나씩 깊게 파고드는 문서 모음입니다. 각 문서는 **독립적으로 읽을 수 있도록** 작성되었지만, 아래의 추천 순서대로 읽으면 개념이 차곡차곡 쌓여 이해가 훨씬 빠릅니다.

---

## 추천 읽기 순서

처음 오신 분은 이 순서를 따라가 보세요. 각 단계에서 배운 개념이 다음 단계의 전제가 됩니다.

| 순서 | 문서 | 주제 | 난이도 | 한 줄 요약 |
|------|------|------|--------|-----------|
| 1️⃣ | [액터 모델](actor_model.md) | 액터란 무엇인가 | ★★☆ | 서로 격리된 액터가 메시지로만 대화하는 프로그래밍 모델과 생명주기 |
| 2️⃣ | [메시지 시스템](messaging.md) | 액터 간 우편물 | ★★★ | 타입 소거·SBO 최적화로 만든 96바이트 메시지 컨테이너와 통신 패턴 |
| 3️⃣ | [작업 분배](work_dispatch.md) | 누가 언제 실행하나 | ★☆☆ | 실행 토큰·inFlight 슬롯으로 "액터당 한 곳에서만 실행"을 보장하는 방법 |
| 4️⃣ | [동시성](concurrency.md) | 빠르고 안전하게 | ★★★★ | 락프리 큐·작업 스틸링·메모리 오더링으로 핫 패스에서 뮤텍스 제거하기 |
| 5️⃣ | [메모리 관리](memory.md) | 데이터를 어디에 담나 | ★★☆ | TCMalloc 스타일 3계층 풀 할당자로 할당 잠금 경쟁 없애기 |
| 6️⃣ | [슈퍼바이저](supervision.md) | 죽으면 어떻게 하나 | ★★☆ | 액터 실패 시 재시작 전략 적용과 데드 레터로 유실 방지하기 |
| 7️⃣ | [인프라 계층](infrastructure.md) | OS와 연결하기 | ★★☆ | 포트-어댑터 패턴으로 epoll·timerfd·소켓을 코어에 깔끔히 꽂는 법 |

> 💡 **첫 읽기 팁**
> - 난이도는 "필요한 배경 지식" 기준입니다. 순서대로 읽으면 앞 문서가 뒷 문서의 전제가 되어 ★★★★도 따라올 수 있습니다.
> - **4️⃣ 동시성**은 성격이 조금 다릅니다 — 처음부터 끝까지 정독하는 문서가 아니라 *깊이 참조용*입니다. 첫 읽기에서는 "요약", "메모리 오더링 입문", "설계 원칙"만 훑고, 나머지는 필요할 때 찾아오세요.
> - C++20 문법(`requires`, fold expression 등)이 낯설면 코드 예시의 *의도*만 따라가도 충분합니다. 각 문서는 문법 설명 없이도 흐름이 이해되도록 쓰여 있습니다.

## 문서별 상세

### [actor_model.md](actor_model.md) — 시작점

"V² Engine의 모든 구성 요소는 액터다"라는 첫 원칙부터 설명합니다.
`Actor` 기본 클래스, 생명주기 상태 머신, `ActorHandle`의 세대 기반 안전 참조, 컴파일 타임 메시지 검증까지 — 나머지 모든 문서의 전제가 되는 개념입니다.

**먼저 읽으면 좋은 지식:** C++ 클래스/상속, 스레드가 뭔지 정도면 충분합니다.

### [messaging.md](messaging.md) — 통신 규약

액터끼리 주고받는 `Message` 객체의 내부 구조(96바이트 레이아웃, 인라인/풀 저장 모드), 40개 메시지 카탈로그, 그리고 요청-응답·pub-sub 같은 실전 통신 패턴을 다룹니다.

### [work_dispatch.md](work_dispatch.md) — 가장 읽기 쉬운 심화편

식당 비유(주문서=메시지, 호출표=실행 토큰)로 시작해, 왜 액터당 토큰이 1개여야 하는지, `finalize()` 정산 프로토콜이 왜 유실 없이 동작하는지 설명합니다. 실제 성능 버그 (워커를 늘렸는데 처리량 46배 붕괴)를 진단했던 케이스 스터디도 포함되어 있어 "성능 문제를 만났을 때 어떻게 접근하는지"를 배울 수 있습니다.

### [concurrency.md](concurrency.md)

Vyukov MPSC/MPMC 락프리 큐의 구현, 세마포어 웨이크업, 작업 스틸링, 그리고 어느 위치에 어떤 메모리 오더링(`relaxed`/`acquire`/`release`/`acq_rel`)을 쓰는지와 그 근거까지 정리한 참조 문서입니다.

### [memory.md](memory.md)

일반 malloc이 왜 느린지에서 출발해, 스레드 로컬 캐시 → 중앙 캐시 → 슬랩의 3계층 구조, 침입형 프리 리스트, 9개 크기 등급을 도서관 비유와 함께 설명합니다.

### [supervision.md](supervision.md)

액터가 예외로 죽었을 때 OneForOne/OneForAll/None 전략으로 복구하고, 유실된 메시지를 데드 레터 큐에 보관하는 흐름을 감독자 비유로 풀어냅니다.

### [infrastructure.md](infrastructure.md)

epoll 이벤트 루프, timerfd 타이머, self-pipe 시그널 처리, 유닉스 도메인 소켓, JSON 설정 로더, 하드웨어 HAL을 포트-어댑터 관점에서 설명합니다. "코어는 OS를 모른다"라는 설계가 코드에서 어떻게 실현되는지 보여줍니다.
